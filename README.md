# AI Agent Element Selector

Chrome/Chromium-расширение для работы с живой страницей прямо в браузере. Оно решает три задачи: помечает DOM-элементы комментариями, позволяет быстро править страницу в рантайме и собирает из этого промпт для ИИ-агента.

Это не визуальный редактор сайта и не система codegen. Расширение работает поверх открытой страницы, хранит локальное состояние в `chrome.storage.local` и копирует результат в буфер обмена. Дальше вы уже передаете этот промпт агенту и переносите изменения в код.

## Что умеет

- Аннотировать элементы страницы и привязывать к ним комментарии.
- Редактировать текст, размеры, позицию и inline-стили прямо в DOM.
- Вставлять wireframe-шаблоны в выбранные контейнеры.
- Экспортировать аннотации, правки и шаблоны в текстовый промпт для агента.
- Восстанавливать состояние страницы после перезагрузки.
- Поддерживать `undo` и `redo` для правок.

## Установка

1. Склонируйте репозиторий или скачайте его как архив.
2. Откройте `chrome://extensions/`.
3. Включите `Developer mode`.
4. Нажмите `Load unpacked`.
5. Выберите папку этого проекта.

Расширение не требует сборки. В репозитории уже лежит готовый MV3-пакет.

## Разрешения

- `activeTab` - работать с активной вкладкой.
- `clipboardWrite` - копировать промпты в буфер обмена.
- `storage` - хранить аннотации, правки и шаблоны локально.
- `scripting` - доинжектировать content scripts в уже открытые вкладки.

## Быстрый старт

1. Откройте нужную страницу.
2. Нажмите на иконку расширения в тулбаре или используйте `Ctrl + Shift + S`.
3. На странице появится панель `AI Annotator`.
4. Выберите один из режимов: `Аннотация`, `Редактировать` или `Шаблоны`.
5. Внесите комментарии, правки или плейсхолдеры.
6. Нажмите `Скопировать все агенту`.

Клик по иконке расширения работает как global toggle. Отдельный popup сейчас в `manifest.json` не подключен, поэтому основной вход в инструмент - это иконка расширения, горячая клавиша и панель, встроенная в страницу.

## Режимы работы

### Аннотация

Режим для точечных замечаний по DOM.

Как это работает:

1. Включите `Аннотация`.
2. Кликните по элементу на странице.
3. Расширение создаст заметку, привязанную к этому элементу.
4. Введите инструкцию для агента.
5. Нажмите `Enter`, кнопку `✓` или просто уведите фокус, чтобы свернуть заметку.

Что важно:

- Пока вы вводите текст, выбор элементов ставится на паузу.
- `Shift + Enter` оставляет перенос строки.
- `Esc` удаляет текущую новую заметку.
- Свернутая заметка остается на странице как пин с номером.
- Повторный клик по пину снова раскрывает заметку.

### Редактировать

Режим для быстрых правок прямо на странице без правки исходников.

Что можно делать:

- Выбрать элемент кликом.
- Дважды кликнуть по текстовому элементу и редактировать его inline.
- Менять ширину, высоту, `left`, `top`, `font-size`, `line-height`, `font-weight`, `text-align`, цвета, `opacity`, `padding`, `margin`, `border-radius`.
- Двигать элемент мышью или стрелками.
- Менять размер через resize handles.
- Открывать контекстное меню и скрывать, удалять, клонировать элемент или оборачивать его в `div`.

Что важно:

- Все изменения происходят только в DOM текущей страницы.
- Исходные файлы проекта расширение не меняет.
- `Enter` в inline-редактировании сохраняет текст.
- `Esc` в inline-редактировании отменяет правку.
- `Esc` в edit mode снимает выделение, а если ничего не выделено - выключает режим.
- Стрелки двигают выбранный элемент на `1px`, `Shift + стрелка` - на `10px`.

### Шаблоны

Режим для вставки временных wireframe-блоков в существующую страницу.

Как это работает:

1. Откройте `Шаблоны`.
2. Выберите шаблон из библиотеки.
3. Кликните по контейнеру, в который нужно его вставить.
4. Расширение добавит временный блок `ai-selector-template-block`.
5. Нажмите `Скопировать агенту`, чтобы получить задание на замену этих плейсхолдеров реальной версткой.

Что важно:

- Это именно временные блоки для проектирования, а не готовые компоненты.
- В промпт уходит описание шаблона и селектор контейнера.
- В агентском промпте отдельно указывается, что плейсхолдеры нужно удалить и заменить нормальным HTML/CSS.
- `Esc` отменяет выбор контейнера до вставки.

## Горячие клавиши

- `Ctrl + Shift + S` - включить или выключить расширение.
- `Ctrl + Z` - `undo`.
- `Ctrl + Y` - `redo`.
- `Ctrl + Shift + Z` - `redo`.
- `Enter` в заметке - сохранить и свернуть.
- `Shift + Enter` в заметке - новая строка.
- `Enter` в inline-редактировании текста - сохранить.
- `Esc` - отмена текущего действия или выход из подрежима.

## Что копируется агенту

Кнопка `Скопировать все агенту` собирает данные из локального состояния по всем сохраненным страницам и формирует один текстовый промпт.

В промпт попадает:

- URL страницы.
- Список аннотаций с CSS-селекторами и текстом комментария.
- HTML-фрагменты элементов для аннотаций.
- Список правок по селекторам: текст, стили, позиция, размеры, скрытие, удаление, клонирование.
- Список вставленных шаблонов и контейнеров, в которые они были добавлены.

Детализация промпта настраивается в панели:

- `brief` - минимум контекста.
- `normal` - селекторы и укороченный HTML.
- `extended` - больше HTML-контекста.

Отдельно можно копировать:

- только изменения из edit mode
- только задания по вставленным шаблонам

## Хранение состояния

Состояние хранится в `chrome.storage.local`.

Что сохраняется:

- аннотации
- журнал правок `editChangesLog`
- примененные inline-стили
- вставленные шаблоны

Ключ хранения строится как:

`ai-annotator-v2:<origin><pathname>`

Это значит:

- query string и hash в ключ не входят
- состояние живет отдельно для каждого пути
- TTL сохранения - 7 дней

При повторной загрузке страницы расширение пытается восстановить:

- свернутые аннотации
- список правок
- примененные стили
- список шаблонов

## Поведение на вкладках и SPA

- Глобальное состояние включения хранится отдельно в `chrome.storage.local`.
- Если расширение включено, оно остается активным после перезагрузки страницы.
- При SPA-навигации расширение ловит смену URL и пробует переинициализироваться.
- На системных страницах вроде `chrome://` content scripts не работают.

## Ограничения

- Расширение не меняет исходный код сайта или приложения.
- Все DOM-правки временны, пока вы не перенесете их в проект вручную или через агента.
- Экспорт в буфер обмена не равен автоматическому применению патча.
- Состояние привязано к `origin + pathname`, а не к полному URL.
- Если структура DOM заметно изменилась, часть селекторов может перестать точно указывать на прежние элементы.

## Структура проекта

### Точка входа и интеграция

- `manifest.json` - MV3-манифест, права и список content scripts.
- `background.js` - глобальный toggle и реакция на обновление вкладок.
- `init.js` - инициализация и повторная инициализация расширения на странице.

### Основной UI

- `ui.js` - master panel, copy actions, настройки и общие кнопки.
- `content.css` - стили overlays и page-level элементов.
- `shadow.css` - стили панели и внутренних виджетов в `Shadow DOM`.

### Режимы работы

- `annotations.js` - заметки, пины и позиционирование аннотаций.
- `inspect.js` - выбор элементов на странице.
- `edit.js` - edit mode, drag, resize, inline text edit, properties panel.
- `templates.js` - библиотека wireframe-шаблонов и их экспорт.

### Состояние и утилиты

- `state.js` - общее runtime-состояние.
- `persist.js` - сохранение и восстановление данных.
- `undo.js` - `undo`/`redo`.
- `helpers.js` - вспомогательные функции.

### Прочее

- `popup.html`, `popup.js` - отдельный UI toggle, который сейчас не подключен в `manifest.json`.
- `walkthrough.md` - старое описание проекта, не синхронизированное с текущим README.

## Локальная проверка

Перед коммитом README имеет смысл прогнать руками минимальный сценарий:

1. Перезагрузить расширение в `chrome://extensions/`.
2. Открыть обычную страницу.
3. Включить расширение по иконке или `Ctrl + Shift + S`.
4. Создать хотя бы одну аннотацию.
5. Сделать хотя бы одну правку в edit mode.
6. Вставить хотя бы один шаблон.
7. Проверить `undo` и `redo`.
8. Проверить, что `Скопировать все агенту` действительно кладет текст в буфер.
9. Перезагрузить страницу и убедиться, что состояние восстановилось.

## Для чего это подходит лучше всего

- быстрые UX-ревью на живом интерфейсе
- подготовка задач для ИИ-агента по готовой странице
- прототипирование недостающих блоков без захода в код
- перенос точечных DOM-правок в исходники после визуальной проверки

Если вам нужен инструмент, который сразу меняет файлы проекта, это не он. Здесь рабочий цикл другой: посмотреть страницу, наметить изменения, собрать контекст, передать его агенту, потом уже перенести изменения в код.
